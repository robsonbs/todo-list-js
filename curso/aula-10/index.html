🚀 Missão: Lista na Nuvem

Sua lista já sabe guardar tarefas no navegador. Agora vamos construir o caminho para guardá-las com segurança na internet.

Missão Servidor HTTP Express Banco de dados PostgreSQL Segurança Integração Publicação

🧭 Briefing da missão

Imagine que o navegador é uma ilha: hoje, as tarefas ficam no armazenamento daquele navegador. Para acessar a mesma lista em outro aparelho, precisaremos de um servidor e de um banco de dados.

Ao terminar, você conseguirá:
  • explicar como navegador, backend e banco conversam;
  • ler e montar requisições HTTP para uma API;
  • criar rotas com Express e persistir dados no PostgreSQL;
  • entender por que cada usuário deve acessar apenas suas tarefas;
  • acompanhar o caminho do desenvolvimento local até a publicação.

Pré-requisito: conhecimentos do curso inicial de JavaScript. Não é necessário já saber backend, Express ou banco de dados.

1 A ilha, o servidor e o backend

O navegador executa a interface. O backend é o programa que recebe pedidos, aplica regras e conversa com o banco. Node.js permite executar JavaScript fora do navegador; Express ajuda a organizar as rotas HTTP desse servidor.

Desafio relâmpago: se fechar o navegador, qual parte continua disponível para atender outro aparelho? Resposta: o servidor e o banco, se estiverem publicados e funcionando.

2 HTTP: o correio da web

Uma requisição leva um pedido do cliente ao servidor; uma resposta informa o resultado. O método descreve a intenção: GET consulta, POST cria, PATCH altera parcialmente e DELETE remove. Cabeçalhos dão contexto, o corpo pode carregar JSON, e o status resume o resultado (por exemplo, 200, 201, 400, 401, 404 ou 500). 

Escolha uma missão HTTP para ver a requisição e a resposta.

🗺️ Como interpretar o Mermaid

As colunas são participantes; o tempo avança de cima para baixo. Setas contínuas mostram pedidos e setas tracejadas mostram respostas. O navegador não grava diretamente no banco: ele envia HTTP à API, que decide se a operação é permitida.

3 Express: organizar as entregas

Uma rota combina método e endereço. Middleware é uma etapa que pode inspecionar a requisição antes de chegar à rota — por exemplo, conferir se existe uma sessão. O fluxo didático será: receber → validar → autorizar → executar → responder. 

// Exemplo de rota Express (a versão completa terá tratamento de erros)
app.get('/api/tarefas', exigirLogin, async (req, res) => {
  const resultado = await banco.query(
    'SELECT id, texto, completa FROM tarefas WHERE usuario_id = $1',
    [req.session.usuarioId]
  );

  res.status(200).json({ tarefas: resultado.rows });
});

🔎 Leia a rota

app.get atende consultas GET. exigirLogin roda antes da função principal. O valor $1 é um parâmetro SQL; o ID vem da sessão validada pelo servidor, não de um campo escolhido pelo navegador.

4 Banco de dados: arquivo com regras

Um banco relacional organiza informações em tabelas. Colunas descrevem propriedades; linhas representam registros. Uma chave primária identifica cada registro. Uma chave estrangeira conecta registros relacionados e ajuda a manter os dados consistentes.

erDiagram USUARIOS ||--o{ TAREFAS : possui USUARIOS ||--o{ SESSOES : inicia USUARIOS { uuid id PK string email UK string hash_senha } TAREFAS { uuid id PK uuid usuario_id FK string texto boolean completa } SESSOES { string sid PK uuid usuario_id FK datetime expira_em }

🗺️ Como interpretar o Mermaid

Cada caixa é uma tabela. PK identifica a chave primária e FK uma referência a outra tabela. A ligação USUARIOS ||--o{ TAREFAS significa: uma tarefa pertence a um usuário; um usuário pode ter zero ou muitas tarefas. Assim, o banco registra a propriedade dos dados.

5 PostgreSQL e SQL

PostgreSQL é o sistema que mantém as tabelas e responde a consultas SQL. As operações básicas são criar, ler, atualizar e remover (CRUD). Migrações registram mudanças planejadas no formato do banco. 

-- $1 recebe um valor enviado separadamente pelo driver pg
SELECT id, texto, completa
FROM tarefas
WHERE usuario_id = $1
ORDER BY criada_em DESC;

INSERT INTO tarefas (usuario_id, texto)
VALUES ($1, $2)
RETURNING id, texto, completa;
Desafio da bibliotecária: por que não escrever o ID recebido do navegador diretamente dentro do texto SQL? Porque parâmetros separam dados do comando e ajudam a prevenir SQL injection. Além disso, a propriedade deve vir da sessão, não de um ID arbitrário enviado pelo cliente.

6 Identidade, autorização e segurança

Autenticação responde “quem entrou?”; autorização responde “o que essa pessoa pode acessar?”. A senha nunca é salva em texto: é transformada em um hash com Argon2id. Depois do login, o servidor mantém uma sessão e o navegador recebe um cookie protegido.

sequenceDiagram actor Pessoa participant Browser as Navegador participant App as Express participant DB as PostgreSQL Pessoa->>Browser: Envia tarefa Browser->>App: POST + cookie de sessão + token CSRF App->>App: Valida sessão, CSRF e conteúdo App->>DB: INSERT usando usuario_id da sessão DB-->>App: Registro criado App-->>Browser: 201 Created Browser-->>Pessoa: Confirma a tarefa

🗺️ Como interpretar o Mermaid

A pessoa só inicia a ação. O navegador envia cookie e token CSRF; o Express verifica a sessão e a requisição antes de gravar. O ID usado na consulta é derivado da sessão, o que impede que trocar um identificador na tela dê acesso às tarefas de outra pessoa.

  • Cookie `HttpOnly`: JavaScript da página não lê o cookie de sessão.
  • `Secure`: em produção, o cookie só viaja por HTTPS.
  • `SameSite` e token CSRF: ajudam a proteger ações iniciadas por outro site.
  • Helmet e limite de tentativas: adicionam cabeçalhos de segurança e reduzem abuso.
  • Saída segura: textos de tarefas são exibidos como texto, não como HTML executável.

Regra de ouro: esconder um botão não protege dados. A verificação precisa acontecer no servidor em cada operação.

7 O navegador conversa com a API

O frontend usa fetch para enviar HTTP. Enquanto espera, mostra carregamento; depois verifica se houve sucesso e atualiza a tela. Uma falha de rede não deve apagar o que a pessoa digitou nem fingir que a tarefa foi salva. 

const resposta = await fetch('/api/tarefas', {
  method: 'GET',
  headers: { Accept: 'application/json' },
  credentials: 'same-origin'
});

if (!resposta.ok) {
  throw new Error('Não foi possível carregar as tarefas.');
}

const dados = await resposta.json();
Decisão de migração: a aplicação oferecerá importar tarefas locais depois que a pessoa entrar. A importação será explícita para não misturar dados por acidente entre contas.

8 Publicar a missão na internet

No computador, usamos serviços locais como localhost. Para outras pessoas acessarem, precisamos publicar o backend e o banco, configurar domínio e HTTPS e fornecer segredos por variáveis de ambiente. Um arquivo `.env` local nunca deve ser enviado ao Git.

Critério de sucesso: explicar o percurso navegador → HTTP → Express → PostgreSQL e concluir uma tarefa pela aplicação publicada.
